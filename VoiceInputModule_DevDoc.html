🍎 macOS 原生语音输入法开发文档

文档版本：1.1  |  目标平台：macOS 26 (Tahoe) 及以上，Apple Silicon (M1+)  |  开发语言：Swift 6  |  依赖方式：Swift Package Manager (SPM) + 系统原生框架

1. 项目概述

本项目旨在为 macOS 输入法（如开源的 InputMethodKit 方案）增加本地语音输入功能，完全离线，保护隐私。核心能力包括：

  • 实时语音转文字（边说边显）
  • 基于声纹的说话人过滤（只转写“我”的声音，忽略他人）
  • 本地大语言模型（LLM）后处理（自动添加标点、去除口语词、润色语句）
  • 全局热键唤出录音
  • 语音模块与输入法主程序解耦，通过回调将最终文本传给输入法引擎，由输入法负责文字上屏

所有功能均使用 Apple 原生 API 和 开源 Swift 库 实现，无需额外后端进程，直接集成到输入法主程序中。

3. 技术架构

采用 三阶段并行流水线 架构，所有处理均在设备端完成。

麦克风 (AVCaptureSession) │ ▼ ┌────┴────┐ │ 音频分流 │ └────┬────┘ │ ┌────┴──────────────────────────────┐ │ │ ▼ ▼ SpeechAnalyzer FluidAudio 缓冲区 (实时流式转录) (累积 16kHz Float32 样本) │ │ ▼ ▼ 带时间戳的文字片段 录音结束后执行 (每段含 audioTimeRange) performCompleteDiarization() │ │ └──────────────┬────────────────────┘ ▼ 时间戳对齐匹配 (按 audioTimeRange 重叠度分配说话人) ▼ 仅保留“我”的文本 ▼ FoundationModels 后处理 (添加标点/去除口语词/润色) ▼ 回调传给输入法主控制器 (由输入法负责最终上屏)

4. 核心模块实现

4.1 音频捕获

推荐方案：AVCaptureSession（而非 AVAudioEngine.installTap）

踩坑提醒：AVAudioEngine.installTap 在蓝牙麦克风设备上可能不会触发回调，而 AVCaptureSession 在所有音频设备上均稳定工作。
import AVFoundation

class AudioCaptureManager {
    private let captureSession = AVCaptureSession()
    private let audioQueue = DispatchQueue(label: "audio.capture.queue")
    
    func startCapture() throws {
        captureSession.beginConfiguration()
        guard let audioDevice = AVCaptureDevice.default(for: .audio) else {
            throw NSError(domain: "Audio", code: -1, userInfo: [NSLocalizedDescriptionKey: "No microphone found"])
        }
        let audioInput = try AVCaptureDeviceInput(device: audioDevice)
        if captureSession.canAddInput(audioInput) {
            captureSession.addInput(audioInput)
        }
        captureSession.commitConfiguration()
        captureSession.startRunning()
    }
    
    // 在 AVCaptureAudioDataOutput 的 delegate 中获取音频样本
    func captureOutput(_ output: AVCaptureOutput, didOutput sampleBuffer: CMSampleBuffer, from connection: AVCaptureConnection) {
        // 分流：一路给 SpeechAnalyzer，一路累积给 FluidAudio
    }
}

4.2 实时语音转文字（SpeechAnalyzer）

SpeechAnalyzer 是 macOS 26 引入的原生 API，替代旧版 SFSpeechRecognizer，支持流式输出和时间戳。

import Speech

class SpeechTranscriber {
    private var analyzer: SpeechAnalyzer?
    private var inputBuilder: AsyncStream<AnalyzerInput>.Continuation?
    private var inputSequence: AsyncStream<AnalyzerInput>?
    
    func start() async throws {
        let transcriber = SpeechTranscriber(
            locale: Locale(identifier: "zh-CN"),
            transcriptionOptions: [],
            reportingOptions: [.volatileResults, .alternativeTranscriptions],
            attributeOptions: [.audioTimeRange, .transcriptionConfidence]
        )
        analyzer = SpeechAnalyzer(modules: [transcriber])
        let (stream, continuation) = AsyncStream<AnalyzerInput>.makeStream()
        inputSequence = stream
        inputBuilder = continuation
        try await analyzer?.start(inputSequence: stream)
        
        Task {
            for try await result in analyzer!.results {
                // result.isFinal 为 true 表示最终结果，否则为实时部分结果
                // result.text 转写文字
                // result.audioTimeRange 时间戳
                handleTranscription(result)
            }
        }
    }
    
    func feedAudio(_ sampleBuffer: CMSampleBuffer) {
        let input = AnalyzerInput(sampleBuffer: sampleBuffer)
        inputBuilder?.yield(input)
    }
}

4.3 说话人分离与声纹识别（FluidAudio）

FluidAudio 是一个开源的 Swift SDK，基于 CoreML，提供离线的说话人分离、声纹提取和识别功能。

安装：

// Package.swift
dependencies: [
    .package(url: "https://github.com/FluidInference/FluidAudio.git", from: "0.0.3")
]

使用示例：

import FluidAudio

class SpeakerDiarizer {
    private let diarizer = DiarizerManager()
    private var accumulatedSamples: [Float] = []
    
    func initialize() async throws {
        try await diarizer.initialize() // 首次运行会下载约 700MB 模型
    }
    
    func accumulateAudio(sampleBuffer: CMSampleBuffer) {
        let floatSamples = convertCMSampleBufferToFloat32(sampleBuffer) // 需实现转换
        accumulatedSamples.append(contentsOf: floatSamples)
    }
    
    func finishAndDiarize() async throws -> [SpeakerSegment] {
        let segments = try await diarizer.performCompleteDiarization(
            audioSamples: accumulatedSamples,
            sampleRate: 16000
        )
        return segments
    }
}

声纹注册（录入“我”的声音）：

let mySpeaker = Speaker(name: "我")
// 提取声纹嵌入（具体 API 可参考 FluidAudio 文档）
// 后续识别时，匹配到的声音会被标记为 "我"
注意：FluidAudio 提供 Sortformer（稳定，最多4人）和 LS-EEND（复杂场景，最多10人）两种模型。对于输入法场景，推荐使用 Sortformer 以提高声纹识别的可靠性。

4.4 时间戳对齐与过滤

将 SpeechAnalyzer 输出的文字片段（含 audioTimeRange）与 FluidAudio 输出的说话人片段（含起始时间）进行重叠度匹配，分配说话人 ID，然后只保留属于“我”的文本。

func alignAndFilter(transcriptions: [TranscriptionSegment], speakerSegments: [SpeakerSegment]) -> String {
    var myTexts: [String] = []
    for trans in transcriptions {
        // 找到与 trans.audioTimeRange 重叠时间最长的 speakerSegment
        let best = speakerSegments.max(by: { a, b in
            overlapDuration(trans.audioTimeRange, a.timeRange) <
            overlapDuration(trans.audioTimeRange, b.timeRange)
        })
        if let best = best, best.speakerId == "我" {
            myTexts.append(trans.text)
        }
    }
    return myTexts.joined()
}

4.5 LLM 后处理（FoundationModels）

利用 Apple Intelligence 的 FoundationModels 框架，在设备端对原始转写文本进行润色。

import FoundationModels

class TextPolisher {
    private let session = LanguageModelSession()
    
    func polish(_ rawText: String) async throws -> String {
        let prompt = """
        你是一个文本润色助手。请对以下语音转写的原始文本进行润色：
        1. 添加合适的标点符号
        2. 去除口语化的填充词（如"嗯"、"那个"）
        3. 纠正同音字错误
        4. 将零散短句组织成流畅的书面语句

        原始文本：\(rawText)

        请只返回润色后的文本，不要添加任何额外说明。
        """
        let response = try await session.respond(to: prompt)
        return response.content
    }
}
注意：首次调用会有 2-3 秒的模型加载延迟，建议在 App 启动时预热（调用一次简单的请求）。

4.6 结果回调与上屏

语音模块不直接处理文字上屏，而是通过委托或回调将最终文字传递给输入法主控制器，由输入法负责插入到当前光标位置。

protocol VoiceInputDelegate: AnyObject {
    func voiceInputDidFinish(with text: String)
}

class VoiceInputManager {
    weak var delegate: VoiceInputDelegate?
    
    private func finishRecording() {
        // ... 经过所有处理后得到最终文本 finalText
        DispatchQueue.main.async {
            self.delegate?.voiceInputDidFinish(with: finalText)
        }
    }
}

在输入法主控制器（例如 InputController）中实现该委托，并在回调中调用 insertText: 等方法上屏。

4.7 全局热键（CGEventTap）

使用 CGEventTap 监听全局按键（如 Fn+Space）来启动/停止录音。

class HotKeyManager {
    private var eventTap: CFMachPort?
    
    func startListening() {
        let eventMask = (1 << CGEventType.keyDown.rawValue)
        guard let tap = CGEvent.tapCreate(
            tap: .cgSessionEventTap,
            place: .headInsertEventTap,
            options: .defaultTap,
            eventsOfInterest: CGEventMask(eventMask),
            callback: { (proxy, type, event, refcon) -> Unmanaged<CGEvent>? in
                // 判断按键组合是否为 Fn+Space
                // 若匹配，触发录音开始/停止
                return Unmanaged.passUnretained(event)
            },
            userInfo: nil
        ) else { return }
        eventTap = tap
        let runLoopSource = CFMachPortCreateRunLoopSource(kCFAllocatorDefault, tap, 0)
        CFRunLoopAddSource(CFRunLoopGetCurrent(), runLoopSource, .commonModes)
    }
}
注意：CGEventTap 回调不在主线程，需通过 DispatchQueue.main.async 更新 UI 或触发动作。

5. 集成开源库的步骤与潜在冲突解决

本项目主要依赖的开源库是 FluidAudio（通过 SPM 引入），其余为系统框架。

5.1 SPM 集成

在项目根目录的 Package.swift 中添加：

dependencies: [
    .package(url: "https://github.com/FluidInference/FluidAudio.git", from: "0.0.3")
]

5.2 版本兼容性

  • FluidAudio 要求 macOS 14+，但我们已限制为 26+，因此无冲突。
  • FluidAudio 依赖 CoreML 和 Accelerate，均为系统自带。
  • 如果输入法本身使用了其他音频处理库（如 AudioKit），需注意音频格式转换（FluidAudio 需要 16kHz 单声道 Float32），可通过 AVAudioConverter 转换。

5.3 代码签名与权限

  • 应用必须使用有效开发者证书签名（或开发时用 - 临时签名）。
  • Info.plist 必须包含：
    • NSMicrophoneUsageDescription
    • NSSpeechRecognitionUsageDescription
  • 如果使用全局热键，需要在系统设置中授予 辅助功能 权限（用于监听按键），但也可以选择使用输入法自带的热键（如通过 InputMethodKit 的菜单或快捷键设置），这样可避免额外权限。

5.4 沙盒限制

  • 如果输入法运行在沙盒中，需要请求 com.apple.security.device.audio-input 权限。
  • 若使用 CGEventTap 可能需要 com.apple.security.automation.apple-events，但建议优先使用输入法框架提供的快捷键机制，以减少权限依赖。

5.5 模型下载管理

  • FluidAudio 首次使用时会下载约 700MB 的 CoreML 模型，应提供进度指示。
  • SpeechAnalyzer 和 FoundationModels 的模型由系统自动管理（通过 AssetInventory），无需额外代码。

5.6 多开源项目参考

如果需要参考完整实现，可以借鉴以下开源项目（MIT 或类似宽松协议），它们均展示了如何整合这些技术：

  • ambient-voice：完整菜单栏应用，含音频捕获、SpeechAnalyzer、FluidAudio 和屏幕上下文。
  • TranscriberKit：封装了转录+分离逻辑的 Swift 库，使用 Actor 并发。
  • Megaphone：集成 FoundationModels 做后处理的语音输入示例。
注意：直接复制代码时注意遵守各自的许可证条款。

6. 性能优化建议

优化点方法
减少音频延迟使用 AVCaptureSession 而非 AVAudioEngine，设置合适的音频缓冲区大小
降低 LLM 延迟App 启动时预热 LanguageModelSession（发送一次简单请求）
减少内存占用音频累积时使用 [Float] 而非 CMSampleBuffer 保留；及时释放不再需要的样本
提高过滤准确率在录音结束后使用离线分离（而非流式），精度更高（DER ~15% vs 26%）
多线程将音频捕获、转录、分离分别放在不同 DispatchQueue 或 Task 中，避免阻塞主线程
